# Skill: Project Kanban Management

**Purpose**: Maintain a clear, living Kanban board that reflects current sprint reality and supports fast coordination across roles.

**Steps**:

1. Open or create the current sprint Kanban (usually in GitHub Projects).
2. Ensure all tasks have correct columns: Backlog → To Do → In Progress → Review → Done.
3. Update task status at the start and end of each work session.
4. Add blockers, dependencies, and next-action comments on every card.
5. Keep WIP (Work In Progress) limits respected per role.

**Success Criteria**:

- Every active task has an owner, clear next action, and deadline.
- Board reflects reality within 4 hours of any status change.
- No card stays in "In Progress" longer than 2 days without update.

**Escalation**: If blocked for more than 1 day or requires scope change, escalate to Personal Role immediately.
