# Skill: Project Roadmap Maintenance

**Purpose**: Keep a high-level, living roadmap that aligns short-term sprints with long-term vision without over-committing.

**Steps**:

1. Review the current roadmap document (usually `ROADMAP.md` or GitHub Project view).
2. Map upcoming sprints to major themes or milestones.
3. Mark completed items and move them to "Done / Shipped".
4. Add new high-level items only after Core Role approval.
5. Update estimated timelines based on actual velocity from A.E.D. rituals.

**Success Criteria**:

- Roadmap stays realistic and updated after every sprint.
- No more than 3 major themes active at any time.
- All items are traceable to Core vision.

**Escalation**: Any addition or major timeline change must be approved by Core Role before updating.
